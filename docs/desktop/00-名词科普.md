## 1. Tauri 2 + Python sidecar 是什么

### 1.1 先看你现在的处境

cizha 现在是「Vue 网页 + FastAPI 后端」，用浏览器访问 `127.0.0.1:8000`。

要做成桌面软件，本质问题是：**怎么让用户双击一个图标就能用，而不是开终端、敲命令、再开浏览器？**

### 1.2 桌面软件的三种"穿法"

| 流派 | 做法 | 代价 |
|---|---|---|
| **原生重写** | 用 Swift 重写整个界面（Easydict 走的路） | 6 千行重写，且只能支持 macOS |
| **自带浏览器**（Electron） | 把一个完整的 Chrome 塞进 App 里 | 安装包 **150MB+**，内存占用高 |
| **借用系统浏览器**（Tauri） | 不塞浏览器，用系统**自带**的那个 | 安装包 **10MB 级** |

Tauri 走第三条路。

### 1.3 Tauri 到底做了什么

> **一句话比喻：Tauri 是一个相框。**

- 你的 Vue 页面 = **照片**（原样放进去，不用重画）
- 系统自带的浏览器内核 = **相框里的玻璃**
  - macOS → WKWebView（Safari 的内核）
  - Windows → WebView2（Edge 的内核，Win10/11 一般已内置）
  - Linux → WebKitGTK
- 用 **Rust 语言**写的那个"框" = **相框的木边和背板**（窗口、托盘、快捷键、菜单、更新）

**关键收益：前端代码零改动。** `npm run build` 出来的 `dist/` 直接塞进相框就是一个 App。之所以只有十几 MB，是因为它**不带浏览器**，用的是系统已有的。

### 1.4 sidecar 是什么

`sidecar` 是摩托车的**边三轮**：挂在主车旁边、跟主车一起跑的那节车厢。

在 Tauri 里，它指**跟 App 一起打包、并交由 App 管理生命周期的另一个可执行程序**。

cizha 的 FastAPI 现在需要你自己开终端跑 `uvicorn`；桌面版的形态变成：

```
你双击图标
   ↓
Tauri 外壳（Rust）启动
   ├─ 打开窗口，显示你的 Vue 页面
   └─ 顺手把 Python 后端拉起来（这就是 sidecar）
         ↓
   页面去请求 127.0.0.1:<随机端口>，业务逻辑一切照旧
   ↓
你关窗口 / 退出 → Tauri 负责把 Python 进程杀掉
```

### 1.5 为什么保留 Python 而不重写

你 210 个测试、六档复习算法、SSE 流式代理、SQLite 幂等迁移，**全在 Python 里**。重写等于把最难验证的部分推倒重来，收益为零。

代价是要把 Python 也打包进去。这一步用 **PyInstaller**：

> PyInstaller 把「Python 解释器 + 你的代码 + 所有依赖库」压成一个可直接运行的二进制文件。
> **用户电脑上不需要装 Python。**

所以完整的一句话是：

> **Tauri 2 + Python sidecar = 一个十几 MB 的壳，套住你现有的 Vue 页面，同时随身带着一个打包好的 Python 后端。**

## 2. Rust 是什么，为什么必须装它

### 2.1 Rust 是一门编程语言

2015 年发布 1.0。三个特点：

1. **编译成机器码**（不像 Python 需要解释器）；
2. **没有垃圾回收**（不像 Java/JS 需要 GC 停顿）；
3. **内存安全**——编译器在编译期就拦掉大量崩溃和并发 bug（这是它最出名的地方）。

今天 Linux 内核、Windows 系统组件、Chrome 的部分模块里都有 Rust 代码。

### 2.2 为什么你需要它

因为 **Tauri 这个"相框"本体是用 Rust 写的**。

凡是"框"上的活，都必须写 Rust：

- 做托盘图标、菜单
- 注册全局快捷键
- 拉起 Python 子进程、读取它报告的端口号
- 保证只能开一个窗口（单实例）
- 读写系统通知、开机自启

**但要写多少？大概 100~300 行胶水代码。**

你不需要"学会 Rust 去做项目"，你只需要"能改这段代码"。这跟"会一点 SQL"和"成为 DBA"的区别类似。

### 2.3 装的是什么，用户需要装吗

你装的是**编译器工具链**（`rustc` 编译器 + `cargo` 包管理和构建工具），**只在开发时用**。

> **比喻：装修房子要买电钻。**
> 电钻只在你装修那几周用；住进去的人不需要电钻。
> Rust 就是你的电钻——**最终用户拿到的是编译好的 `.app` / `.exe`，他们电脑上不需要 Rust。**

### 2.4 心理准备：第一次编译很慢

第一次 `cargo build` 要编译几百个依赖 crate，**5~15 分钟**（之后再改代码就是秒级增量编译）。这是"装 Rust"的全部痛苦，别赶在发布前做。

### 2.5 完全不想碰 Rust 的两条替代路

| 替代方案 | 语言 | 代价 |
|---|---|---|
| **Electron** | 全 JS/TS | 安装包 150MB+，内存占用高，但生态最成熟 |
| **pywebview** | 全 Python（保留 FastAPI） | 托盘/快捷键/更新都要自己拼轮子，系统能力弱 |

## 3. macOS 签名：不签名到底能不能装

**先纠正一个常见误解：不是"装不上"，而是"会吓退大部分普通用户"。**

真实情况分三种，差别很大。

### 情形 A：你自己编译、自己用 → 双击就开

因为文件是**你本机编译出来的**，不是"从网络下载的"，系统不会给它打隔离标记。**没有任何提示，直接能跑。**

**开发阶段你完全不需要签名。**

### 情形 B：发给别人，对方从浏览器下载 → 会被拦

流程是这样的：

```
浏览器下载 .dmg → 系统给文件打上 com.apple.quarantine（隔离）标记
        ↓
用户双击 App → Gatekeeper（守门人）上场检查
```

- **没签名**：提示"无法打开，因为无法验证开发者"
- **签了名但没公证**：一样被拦（苹果要求的是"已签名 **且** 已公证"）
- **macOS 15 起**：以前"按住 Control 点右键 → 打开"这个经典旁路**已被取消**。用户得去
  `系统设置 → 隐私与安全性 → 安全性 → 仍要打开`，多一次确认。

### 情形 C：用户用命令行绕过

```bash
xattr -dr com.apple.quarantine /Applications/词札.app
```

这条命令删掉隔离标记，之后就能正常打开。**能解决，但要求用户会开终端。**

### 3.1 结论

> **不签名 ≠ 装不上，而是 ≠ 普通用户愿意装。**

| 受众 | 不签名可以吗 |
|---|---|
| 你自己 | ✅ 完全没问题 |
| 愿意折腾的开发者（掘金读者） | ⚠️ 可以，但你要给出一条命令 |
| 普通用户（CSDN 大量读者、Windows 转 Mac 用户） | ❌ 一个"已损坏，请移到废纸篓"的弹窗就结束了 |

### 3.2 签名和公证是两件事

| | 做什么 | 谁做 | 费用 |
|---|---|---|---|
| **签名**（codesign） | 用证书给 App 盖一个"是我发的、没被篡改"的戳 | 你，用 Developer ID 证书 | 含在会员费里 |
| **公证**（notarization） | 把 App 上传苹果云端扫描恶意代码，通过后拿票据 | 你提交，苹果自动审（通常几分钟） | 同上 |

**只有签名没有公证，照样被拦。两个都要。**

### 3.3 三条路线

| 路线 | 成本 | 体验 |
|---|---|---|
| **Apple Developer Program** | **$99/年**（约 ¥688） | 用户双击就开，最顺 |
| **发未公证版** | 免费 | README 写清 `xattr` 命令，转化率大约砍半 |
| **Homebrew Cask 分发** | 免费（但要会写 cask 配方） | 因为不是浏览器下载，通常不会被加隔离标记，可绕开弹窗 |

### 3.4 一个开发期才会遇到的坑（容易忽略）

**没签名时，每次重新编译，App 的"辅助功能"系统授权可能被重置**——你得去系统设置里重新勾一遍。

等你做划词功能时，一天要重新编译几十次，**这个坑会非常折磨人**。

对策：开发期至少做 **ad-hoc 签名**（本地免费签名，`codesign -s -`），保持签名指纹稳定，系统授权就不会反复失效。

## 4. GPL 是什么

### 4.1 关键词：copyleft（传染性）

> **比喻：**
> MIT / Apache 这类宽松许可证是"**开放的花园**"——你可以进去拿花，拿回去随便种，不要求你也开放。
> GPL 是"**进去的东西也必须开放**"——你只要把 GPL 的代码拿进你的项目并分发，**你的整个项目就得变成 GPL**。

**Easydict 是 GPL-3.0；cizha 是 Apache-2.0。**

### 4.2 具体规则

| 你的行为 | 后果 |
|---|---|
| 复制 Easydict 的一段代码进 cizha 并**分发** | ❌ **整个 cizha 必须改成 GPL**：公开全部源码，且允许别人任意再分发 |
| 改了 Easydict 的代码再发布 | ❌ 同上，且必须标注你改了什么 |
| 只是**读它的源码学思路**，然后自己写 | ✅ 完全没问题。**思路不受版权保护，实现受** |
| 只是**运行** Easydict | ✅ 没问题（GPL 约束的是分发，不是使用） |
| 你的程序通过 **HTTP 调它** / 读它**写出的数据文件** | ✅ 一般不算衍生作品（没有复制代码）。*但这不是法律意见* |
| 把 GPL 代码和 Apache 代码混编成一个程序 | ❌ 许可证本身冲突 |

### 4.3 对 cizha 的具体含义

- **Easydict 的代码，一行都不能抄**——包括它那套划词实现。
- 它引用的 `SelectedTextKit` 是作者自己维护的库，**许可证要单独确认**（若为 GPL，同样不能进你的项目）。
- **但"用 `AXUIElement` 这个苹果系统 API 去读选区"这个思路可以照用**，因为那是苹果的公开 API，不是 Easydict 的代码。

> **类比：** Easydict 用"菜刀"切菜，你学着用菜刀切菜完全合法；但你不能抢走它那把菜刀（它的代码）。

## 5. "和 Easydict 联动"到底是联的什么

**这句要精确成两条路，因为两条路的机制完全不同。**

### 路 A：搬"笔记本"（文件级 · 离线）

Easydict 有个功能叫 **VocabularyNotebook**（词本）。开启后，你每查完一个词，它就把结果**追加写进一个 `words.jsonl` 文件**。

关键细节（已从源码确认）：

| 项 | 值 |
|---|---|
| 文件名 | `words.jsonl`（固定） |
| 位置 | **用户自己选的目录**（设置 → 高级 → 词本目录），默认为空 = 功能关闭 |
| 格式 | 每行一条 JSON（JSONL） |
| 时间格式 | 本地时区 ISO 8601，如 `2026-10-22T19:09:12+08:00` |

每一行的结构：

```jsonc
{
  "text": "transformer",              // 查询文本（单词或整句）
  "sourceLanguage": "en",             // BCP-47
  "targetLanguage": "zh",
  "translatedText": "变换器",          // 译文，可能没有
  "timestamp": "2026-10-22T19:09:12+08:00",
  "dictionaryEntry": {                // 整句/流式查询时为 null
    "phonetics": [{ "word": "transformer", "language": "en",
                    "value": "trænsˈfɔːrmər", "accent": "us",
                    "speakURL": "https://..." }],
    "parts": [{ "part": "n.", "means": ["变换器", "变压器"] }],
    "exchanges": [...], "tags": [...],
    "etymology": null, "synonyms": [...], "antonyms": [...], "collocation": [...]
  }
}
```

**cizha 要做的事**：读这个文件 → 转成词条 → 导入词库。

- ✅ 不需要 Easydict 开着
- ✅ 一次性迁移历史词，也支持以后定期同步
- ⚠️ 需要用户自己在 Easydict 里开启并选目录（默认是关的）

### 路 B：问"你现在选了什么"（请求级 · 在线）

Easydict 在本机开了个 HTTP 服务（默认 `127.0.0.1:8080`），提供：

```text
GET  /selectedText      ← 返回你此刻在任意软件里选中的文本
POST /translate         ← 同步翻译
POST /streamTranslate   ← SSE 流式翻译
POST /detect            ← 语言检测
```

cizha 要做的事：请求 `/selectedText` → 拿到文本 → 灌进搜索框。

- ✅ 省掉复制粘贴，等于白嫖到"划词"能力
- ⚠️ 需要 Easydict 开着 + 用户在设置里启用该服务

### 5.1 所以你的理解要修正成

你说"让 Easydict 搜到的单词直接存进 cizha"——**方向对，但 cizha 并不"接管" Easydict**。更准确的说法是：

> **① 读 Easydict 留下的查询记录（文件）→ 搬进词库；**
> **② 问 Easydict 当前的选区（接口）→ 喂给 cizha 查询。**

cizha **不**接管 Easydict 的界面、**不**要求你必须用 Easydict 查词、**也**不修改 Easydict 的任何数据。它只是"读它留下的痕迹"或"问它一个问题"。

> **再打个比方**：Easydict 是你的**课堂笔记**，cizha 是**题卡复习系统**。
> 路 A = "把笔记抄进复习系统"；路 B = "你在书上划完重点，直接说：把这个收进题卡"。

### 5.2 字段怎么对应（导入时的映射表）

| Easydict `words.jsonl` | cizha `Word` 字段 | 说明 |
|---|---|---|
| `text` | `abbreviation` | 主词（必填） |
| `translatedText` | `my_meaning` | cizha 里必填，为 null 时用 `parts` 首条兜底 |
| `dictionaryEntry.phonetics[].value`（`accent` = `uk` / `us`） | `phonetic_uk` / `phonetic_us` | 按 `accent` 分流 |
| `dictionaryEntry.parts[].part` + `means[]` | `api_meaning` | 拼成 `n. 变换器；变压器` 这种多行文本 |
| `timestamp` | `created_at` | 保留原始查询时间 |
| `dictionaryEntry.exchanges` / `synonyms` / `antonyms` / `collocation` / `etymology` / `tags` | （无对应） | 可选塞进 `note` 或直接丢弃 |
| — | `cn_term` / `domain_detail` | **Easydict 没有**，导入后可选择性调 LLM 批量补全 |
| — | `examples` | Eaydict 的词典结果通常不带例句，留空数组 |
| — | `review_stage=0` / `next_review_at=今天` / `in_review=1` | 与 cizha 新词入库规则一致 |

**导入时要注意的业务规则：**

1. **跳过整句**：`text` 里含空格、或 `dictionaryEntry == null` 的，多半是句子而非术语，默认不导（可给开关）。
2. **按 `abbreviation` 去重**：已存在的跳过，保证重复导入幂等。
3. **`my_meaning` 是必填**：`translatedText` 为空时必须兜底，否则整个导入事务会失败。
4. **`words.jsonl` 会追加写**：同步时用"最后处理到文件的哪个字节偏移量"做增量，不要每次全量重扫。

## 6. 一页速查表

| 名词 | 一句话解释 |
|---|---|
| **Tauri 2** | 一个十几 MB 的桌面"相框"，用系统自带浏览器显示你现有的 Vue 页面 |
| **Python sidecar** | 把 FastAPI 用 PyInstaller 打成二进制，跟 App 一起装，由 App 拉起和关闭 |
| **Rust** | 写这个"相框"的语言。你只需写 100~300 行胶水；**用户电脑上不需要装** |
| **签名 / 公证** | 自己用不需要；发给普通用户不给钱会弹"已损坏"，但可用 `xattr` 命令绕过，不是绝对装不上 |
| **GPL** | 传染性开源协议。Easydict 是它 → **代码只能学不能抄** |
| **路 A（联动）** | 读 Easydict 写出的 `words.jsonl` → 导入词库（离线、迁移历史） |
| **路 B（联动）** | 请求 Easydict 的 `GET /selectedText` → 拿到当前选区去查（在线、免复制） |

**最重要的一条**：路 A 和路 B **完全不需要 Rust、不需要 Tauri、不需要签名**——它们只是两个后端接口加一个按钮，纯增量，现有项目结构一行都不用改。
