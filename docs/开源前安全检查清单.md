# 开源 / 发版前安全检查清单

> 只要有人提出「开源」「发版」「上传 Release」「公开仓库」，先完整跑一遍本清单并给出报告，
> **未完成检查前不执行任何 Git 推送、建仓、建 Release 操作。**

## 一、触发与顺序

1. 先只读扫描，输出风险清单（分 P0 / P1 / P2）。
2. 与需求方确认处理范围后再动手。
3. 修复 → 质量门禁 → 重建产物 → 发布 → **发布后再复核产物**。

顺序不可颠倒：先推送再检查，等于已经把风险公开了。

## 二、工作区扫描（P0）

- [ ] 密钥：`.env`、`llm_config.json`、`*.pem`、`*.p12`、含 `sk-` / `ghp_` / `AKIA` 的文件
- [ ] 数据：`*.db`、`*.sqlite`、`*.db-wal`、`*.db-shm`、用户导出 CSV
- [ ] 隐私：真实姓名、邮箱、手机号、聊天截图、个人词库内容
- [ ] 本机绝对路径：`/Users/<用户名>`、`C:\Users\`、`/home/<用户名>`
- [ ] 内部文档：`AGENTS.md`、`ARCHITECTURE.md`、`PRD.md`、`.trae/`、`docs/desktop/`、会议记录
- [ ] 垃圾：`.DS_Store`、`demo*.html`、未引用的图片/字体、临时脚本、`dist/`、`_pybuild/`
- [ ] 文件权限：`.env` 至少 `600`

## 三、忽略规则（P0）

- [ ] `.gitignore` 覆盖以上全部条目，且不是「先提交再补忽略」
- [ ] `git status` 干净；`git check-ignore -v <敏感文件>` 能命中
- [ ] 确认没有用 `git add -A` / `git add .` 的习惯性提交

## 四、Git 历史（P0）

- [ ] 全历史搜密钥：`git grep -l "sk-" $(git rev-list --all)`
- [ ] 全历史搜本机路径：`git grep -l "/Users/<用户名>" $(git rev-list --all)`
- [ ] 全历史搜内部文档：检查每条 ref 的 tree，而不只是 HEAD
- [ ] 有命中则重写历史（`git filter-repo` / `filter-branch`），并同步重打 tag
- [ ] 重写后：`reflog expire` + `gc --prune=now`，删除 `refs/original`
- [ ] 用**全新 clone** 复扫，确认敏感内容已不可达

### 容易漏掉的暴露面

- [ ] `refs/pull/<n>/head`：已合并 PR 的 head 仍指向旧提交，**无法用 API 删除**，只能联系 GitHub Support 或重建仓库
- [ ] 已删除的分支仍可通过 commit SHA 直接访问一段时间
- [ ] Fork、Release 附件、Actions artifacts、Pages 缓存都是独立暴露面

## 五、构建产物（P0）

- [ ] PyInstaller spec 的 `datas` 只含前端 `dist` 与 `.env.example`，**不含 `backend/data/`**
- [ ] 打包脚本在复制后二次清洗 `.env`、`llm_config.json`、`*.db*`
- [ ] 产物解包校验：解压 tar.gz / 挂载 dmg，`find` 扫描 `*.db`、`.env`、`llm_config.json`、`data/`
- [ ] 二进制内嵌校验：`pyi-archive_viewer -l` 检查 onefile 内容
- [ ] 仅允许 CI 产出发布包；**禁止手工上传本地构建的安装包**
- [ ] 后端资源清单（`backend-manifest.json`）重新生成，防止打进旧后端

## 六、发布面（P1）

- [ ] 旧版本 Release 附件及时下架（旧包可能含当时未清洗的数据）
- [ ] Actions artifacts 默认对所有可读仓库的人可下载，旧的及时删除
- [ ] 安装包内 `Info.plist` / 版本号与 tag 一致
- [ ] 发布后再次下载**线上产物**复核，而不是只信本地构建结果

## 七、已泄露时的响应（按顺序）

1. 立即下架泄露资产（Release 附件 / artifacts）
2. **轮换密钥**（下架不等于收回，历史下载无法追回）
3. 评估 Git 历史与 PR refs 的暴露范围
4. 修复构建链路，重新发布新版本
5. 在 `CHANGELOG.md` 的安全段记录事件与处理结果

## 八、验收（Definition of Done）

- [ ] 工作区与 Git 历史扫描均无命中
- [ ] 线上产物解包扫描无命中
- [ ] 版本号三处一致，`/api/health` 返回正确
- [ ] 质量门禁：`ruff check app tests`、全量测试、前端构建
- [ ] 已向需求方提交一份「检查了什么、结论是什么、还剩什么风险」的报告

---

**核心原则**：能被下载的东西都要当作已公开；能被 `git log` 找到的东西都要当作永久公开。
